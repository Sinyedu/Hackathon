
# Challenge: Find 10 Hackathon-Winning AI Solutions

Act as a combination of an **AI research engineer, startup founder, hackathon judge, product strategist, and senior full-stack architect**.

We are participating in a highly competitive hackathon lasting approximately **5 hours**. Our goal is to build something genuinely innovative using **open-source AI models**, intelligent automation, and modern development tools.

We don't want another generic chatbot, AI summarizer, PDF assistant, basic RAG application, or superficial AI wrapper.

We want to identify **10 unique, ambitious but achievable solutions** that address real-world problems, demonstrate impressive technical capabilities, and have a legitimate chance of winning.

## 1. Core Requirements

Every proposed solution must:

- **Solve a real problem:** Identify a specific, meaningful pain point affecting individuals, businesses, institutions, or society.
- **Use open-source AI models meaningfully:** AI must be essential to the solution, not an unnecessary feature. Prioritize models with accessible weights and licenses suitable for the proposed use.
- **Include intelligent automation:** The system should independently perform useful multi-step tasks, coordinate processes, analyze information, or trigger actions rather than simply generate text.
- **Be distinctive:** Avoid overused hackathon concepts. Find overlooked problems, unusual applications of existing technology, or unexpected combinations of AI capabilities.
- **Be achievable in 5 hours:** We need a convincing, working MVP, not just mockups or a presentation.
- **Deliver a memorable demonstration:** Judges should understand the problem and see the value within 30–60 seconds.
- **Have real-world potential:** The solution should be useful beyond the hackathon and ideally have potential for commercialization, adoption, or measurable social impact.

## 7. Important Constraints

- We have approximately **5 hours total**, including debugging and preparing the pitch.
- Prioritize genuinely working software over elaborate architecture.
- Prefer free or readily accessible models, datasets, and APIs.
- Avoid solutions requiring proprietary paid models.
- Avoid ideas that depend on unavailable private data, regulatory approval, expensive GPUs, or weeks of model training.

- Be realistic about inference latency, model downloads, hardware limitations, and integration time.

Why Certified Manual Handling Techniques Training is a Must for Healthcare Workers in Ireland - Ireland Safety Training

Ollama is the runtime that loads the model and exposes a local HTTP API. Your Python backend calls that API just like any other service.

Step 1 — Install Ollama
On Linux Mint:

curl -fsSL https://ollama.com/install.sh | sh

For greater control, review the installation script or use Ollama's manual Linux installation instructions.

Verify installation:

ollama --version

Step 2 — Download the model
ollama pull qwen3:1.7b

Then run it:

ollama run qwen3:1.7b

You can test it with:

Are "Tomatoes, case 5kg" and "Tomato Box 5KG"
likely the same product?
You should receive an interpretation of the product descriptions. That is the AI capability DockProof will use.

Step 3 — Access the model from Python
Ollama normally exposes an HTTP API at:

http://localhost:11434

You don't need LangChain, an agent framework, or a special SDK.

Install the Python dependencies:

pip install requests pydantic

Here's a minimal example using structured JSON output.


import requests

response = requests.post(
    "http://localhost:11434/api/chat",
    json={
        "model": "qwen3:1.7b",
        "stream": False,
        "think": False,
        "format": "json",
        "messages": [
            {
                "role": "system",
                "content": (
                    "Match product descriptions. "
                    "Return only JSON with candidate_id "
                    "and needs_review. "
                    "Select only an existing candidate ID "
                    "or null."
                ),
            },
            {
                "role": "user",
                "content": (
                    'Incoming: "Tomato Box 5KG"\n'
                    'Candidates: [{"id":"P001",'
                    '"description":"Tomatoes, case 5 kg"},'
                    '{"id":"P002",'
                    '"description":"Potatoes, 10 kg"}]'
                ),
            },
        ],
        "options": {"temperature": 0},
    },
    timeout=60,
)

An expected response shape would be:

{
  "candidate_id": "P001",
  "needs_review": false
}

That's an illustrative output, not a guaranteed model response. Your backend must validate the JSON and verify that P001 is an actual supplied candidate.

For production-quality structured output, use Ollama's JSON Schema support with Pydantic, not just "format": "json".
